# デザインブリーフ: liscov

更新: 2026-10-08 (合意: 2026-10-08)

画面のデザインを決めるときの前提。トークン・画面の構成・見た目の判断は、ここに書いたことから理由を引く。
書き方は Claude Code のスキル `app-ui-design` のテンプレートに従う。

## 1. 利用者と状況

- **誰が**: YouTube でライブ配信をしている配信者本人 (VTuber を含む)
- **どこから見るか**: 配信中、メインの画面 (ゲーム・配信ソフト) とは別の位置に置いた小さいウィンドウを、横目で見る。
  配信中は配信ソフト・ゲーム・音声関係など多くのソフトを同時に開いていて、コメントビューアーに割ける面積は小さい。
  4K のディスプレイを 2 枚使う環境でも、liscov のウィンドウは幅 800px・高さ 1090px 程度。
  FHD・WQHD の環境では、同じ見た目の大きさでもっと少ない px になる
- **1 回に見る時間**: 1 秒前後。ゲームや会話の合間にちらっと見る
- **同時にしていること**: ゲームの操作、話すこと、配信の進行。注意はほとんど残っていない。
  コメントの勢いがそれほどなくても、すぐには反応できないことがある

## 2. 画面ごとの読み取る情報の優先順位

### チャット (配信中に見る画面)

1. 新しく来たスーパーチャット・スーパーステッカー・ギフト・メンバーシップ (ギフトを含む)・マイルストーン
2. 新規さん (そのチャンネルで初めてコメントした人) の初回コメント
3. 新規さんの、その配信での 2 回目以降のコメント
4. 常連の、その配信での初回コメント
5. 常連の、その配信での 2 回目以降のコメント ← **ここが強調の標準**
6. 同時接続数・いいね数・チャット率
7. リアクションが上がっているか、その勢い
8. 総コメント数・コメントした人数

- 強調の段階: 5 (通常のコメント) を標準の見た目とし、1〜4 は標準より強く (1 がいちばん強い)、6〜8 は標準より控えめに見せる
- 見落としても困らないもの: 接続の設定、表示の設定
- 状況として常に分かっていたいもの: 接続が切れていないか (切れたときだけ目立てばよい)

### 視聴者の補足情報 (準備)

- 読み仮名・メモの登録は、配信中にその場で、または配信後に行う。普段は頻繁に使わないが、必要なときにすぐ使えること
- 登録した情報は、コメント行の名前の横か直下に、小さく補足として出る

## 3. 面積と密度の目標

### 想定する置き方と大きさ

大きさは CSS の px (Windows の表示スケールを掛ける前)。よくある画面の CSS px は、FHD (100%)・4K (200%) が 1920×1080、
WQHD (125%) が 2048×1152、WQHD (100%)・4K (150%) が 2560×1440。

| 置き方 | 幅 × 高さ |
|---|---|
| 縦置きのディスプレイに全画面 | 1080〜1440 × 1920〜2560 |
| 縦置きのディスプレイの上半分 | 1080〜1440 × 960〜1280 |
| 縦置きのディスプレイの 4 分の 1 (四隅に寄せる) | 540〜720 × 960〜1280 |
| 横置きのディスプレイの横 3 分の 1 | 640〜853 × 1080〜1440 |
| 横置きのディスプレイの横 2 分の 1 | 960〜1280 × 1080〜1440 |
| 任意の場所にフローティング | 上の範囲の中 |

- **幅は 540〜1440px、高さは 960px 以上**。高さには余裕があり、幅のほうが厳しい
- **設計の基準にする大きさ**: 540×960 (いちばん小さい)、640×1080 (いちばんよく使われる想定)、960×1080 (広め)。
  1440px 幅の見栄えは優先しない (§5)

### 密度

- 配信中、固定の UI (状態・操作) が占める高さは、ウィンドウの高さの 15% 以下
- 640×1080 で、優先順位 1 の未対応のものと、直近のコメントが 20 件以上見える
- 現状 (2026-10-08): 640×800 で固定の UI が約 4 割、コメントは約 6 件。
  最小幅が 800px (`tauri.conf.json` の `minWidth`) なので、FHD の横 3 分の 1 や縦の 4 分の 1 には収まらない

## 4. 準備・操作のフロー

| 作業 | 目標 |
|---|---|
| 問題が起きたときに、配信への接続をやり直す | 2 手以内。ただし配信中は目立たせない |
| 特定のコメントを、流れても常に見える状態にしておく | コメントから 1〜2 手。スクロールを止めて戻す必要が無い |
| 特定の視聴者のコメントだけに絞り込む | コメントから 1〜2 手 |
| 読み仮名・メモを登録する | コメントから 2 手で入力を始められる。配信中でも流れを止めずにできる |
| 配信中に使わない操作を隠す・畳む | どれを隠すかを利用者が選べる (固定より、選べるほうがよい) |

## 5. 犠牲にするもの

- **初めて使う人にとっての分かりやすさ**を少し下げ、慣れた人が一瞬で読み取れることを取る。
  ただし、一般的なアプリケーションの UI の慣習の範囲には収める (独自の操作を覚えさせない)
- **広いウィンドウでの見栄え**。広げて使う人は少ない
- **分析 (Analytics) の画面**。使われていないので外す (2026-10-08 に決定)
- **表示件数の細かい選択肢**。表示件数の制限は、性能の低い PC で CPU・メモリの負荷を下げるためのもの。
  その目的に足りる「無制限 (既定)」と「500 件」だけあればよい

## 6. 性格

- 「**引き立て役**」であって「主役」ではない。主役は配信 (配信者とゲーム)。liscov は普段は静かに控え、目を奪わない
- 「**静か**」であって「見落とさせる」ではない。優先順位 1・2 のものが来たときだけは、はっきり分かり、流れても消えない
- 「**慣れた人に速い**」であって「独自の作法を覚えさせる」ではない

## 7. 成功の判定方法

- **ちらっと見るテスト**: 撮影した画面を 1 秒見て、次に答えられる
  - 対応していないスパチャ・ギフト・メンバーシップはあるか。誰からか
  - 新規さんのコメントはあるか
  - 接続は生きているか
- **目を細めるテスト**: 縮小してぼかした画面で、目立つ順が §2 の優先順位と一致する (操作が上位に来ない)
- **実機**: 配信で使い、スクロールして戻らずにスパチャ等に反応できる。見落としが起きない

## 機能への影響 (デザインの範囲を超えるもの)

このブリーフを満たすには、見た目の変更だけでなく、振る舞いの追加・変更が要るものがある。
実装の前に、該当する仕様書 (`docs/specs/`) を更新して合意する。

- 優先順位 1 のものが流れても消えない仕組み (未対応のものを残す、など)
- コメントの固定表示 (ピン留め)、コメントからの視聴者の絞り込み
- 配信中に使わない操作を隠す・畳む設定
- 同時接続数・いいね数の取得 (現状は取得していない)
- ウィンドウの最小幅の引き下げ (現状 `tauri.conf.json` の `minWidth: 800` で、§3 の 540px・640px に収まらない)
- 表示件数の選択肢を「無制限・500 件」に減らす
- 分析画面を外す
- メモをコメント行に出す (読み仮名は現状でも名前の横に出る)
