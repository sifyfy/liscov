# ADR-006: 収益分析・エクスポートを外す

## ステータス

承認

## コンテキスト

デザインの作り直し (docs/design/brief.md) で、配信中にサブモニターでちらっと見る用途を最優先にした。
分析のタブ (スパチャの段階別の件数・時間別・上位貢献者・ギフト) と、CSV・JSON のエクスポートは、配信者 (シフィさん) が使っていなかった。
欲しいのは、スパチャ等をくれた人へのお礼に使う一覧 (配信の最後・月ごとのコミュニティ投稿) で、今の分析の形ではなかった。

## 決定

分析のタブ・エクスポートの画面と、そのためのバックエンド (`commands/analytics.rs` の 4 コマンド・`core/analytics/`・
`AppState::started_at`) を消す。元データ (DB の `messages` の金額の文字列・`superchat_color`・ギフトの metadata) は残す。
段階 (tier) の判定と金額の扱いの約束は `docs/specs/07_revenue.md` に残し、将来の機能が引き継ぐ。

## 理由

### 検討した選択肢

| 選択肢 | メリット | デメリット |
|-------|---------|-----------|
| A. 画面だけ外し、バックエンドを残す | 将来の機能で集計を使い直せるかもしれない | 呼ばれないコマンドと、それを守るテストを持ち続ける。将来の機能の形 (期間・お礼の一覧) は今の集計 (起動中のセッション・段階別の件数) と違い、使い直せる保証が無い |
| B. バックエンドも消し、元データと約束だけを残す | 使われないコードを保守しない。将来の機能を、その用途に合う形で作れる | 将来の機能で段階の判定などを書き直す (約束と表は 07_revenue.md に残る。消す前のコードは git の履歴にある) |

### 採用理由

将来必要なのは元データで、今の形の集計ではない (シフィさん、2026-10-10)。元データは DB に残るので B で失うものは無い。

## 影響

- 画面: 上の行のタブはチャット・視聴者・設定の 3 つになる (02_chat.md)
- フロントエンド: `components/analytics/`・`tabs/AnalyticsTab`・`stores/analytics`・`tauri/analytics`・`types/analytics` と生成した型を消す
- バックエンド: 上のコマンドと `core/analytics/` (単体テストを含む) を消す。DB のスキーマ・マイグレーションは変えない
- E2E: `analytics-current-scope.spec.ts`・`analytics-tab-freeze.spec.ts` を消す。撮影 (design-capture) から分析のタブを外す
